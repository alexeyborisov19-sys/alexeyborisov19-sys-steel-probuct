# Закрытая система управления персональными данными

## Статус

В ветке Этапа 3 локально реализованы закрытые страницы и internal API. Они не опубликованы и не введены в эксплуатацию. По умолчанию `PD_ADMIN_ENABLED=false`: middleware возвращает одинаковый `404` для страниц и API до выполнения ручной production-приёмки. Публичные формы от SQLite не зависят.

## Планируемые маршруты

- `/internal/personal-data/login`, `/internal/personal-data`;
- активные: `leads`, `consents`, `access-log`, `integrity`, `users`, `profile`;
- защищённые заглушки следующего этапа: `subject-requests`, `incidents`, `exports`, `deletions`, `systems`, `legal-documents`, `backups`;
- соответствующие API под `/api/internal/personal-data/**`.

Все страницы и API должны быть динамическими, `no-store`, `noindex`, без Метрики, CookieConsent, ИИ-инженера, внешних виджетов, рекламных пикселей и prefetch персональных URL. Авторизация, RBAC, CSRF, Origin и step-up проверяются на сервере при каждом чувствительном действии.

HTTP-обработчики не применяют миграции автоматически. При несоответствии схемы вход и API завершаются безопасной ошибкой, а изменение схемы выполняется вручную только через `npm run pd:migrate`. В production internal принимает только запросы, прошедшие через канонический HTTPS reverse proxy.

## Источник данных

Первичные JSON остаются техническим источником. Административная SQLite хранит только:

- HMAC точного телефона и e-mail с версией ключа;
- requestId, источник, даты, срок и технические статусы;
- служебный workflow и комментарии;
- аудит доступа, обращения, инциденты, legal hold;
- описания выгрузок, удаления, integrity и backup runs.

Имя, организация, телефон, e-mail, сообщение, диалог и файлы не дублируются в `lead_index`. Поиск по имени/организации — ограниченное серверное сканирование не более 500 индексированных JSON и двух секунд, с разрешением `SEARCH_TEXT`, обязательным основанием и записью события доступа. Точный поиск телефона/e-mail использует versioned HMAC и `SEARCH_CONTACT`.

## Безопасные ошибки

Клиент получает только утверждённый код (`AUTH_REQUIRED`, `PERMISSION_DENIED`, `CSRF_REJECTED`, `STEP_UP_REQUIRED`, `VALIDATION_ERROR`, `NOT_FOUND`, `CONFLICT`, `RATE_LIMITED`, `INTERNAL_ERROR`). Stack trace, абсолютные пути, SQL и содержание записей не возвращаются.

## Условия включения

1. Внешний порт 3000 закрыт и Next.js слушает только loopback.
2. Node.js `>=22.13.0` подтверждён.
3. Каталоги созданы с владельцем `nodejs` и правами `0700`; файлы — `0600`.
4. Все три независимых ключа имеют не менее 32 случайных байт.
5. Миграции, integrity и audit verify успешны.
6. Первый администратор создан вручную и сменил временный пароль.
7. Выполнены тесты, сборка и ручная проверка страниц/API Этапа 3.
8. Подготовленная конфигурация Nginx применена только после отдельного подтверждения; при выключенном флаге приложение продолжает отвечать 404.
9. Юридические документы и внутренние локальные акты утверждены ответственным лицом.

## Важное состояние юридических документов

Публичная политика корректно указывает, что закрытая система ещё не введена в эксплуатацию. До фактического включения это описание менять на «действует» нельзя. Перед production-включением оператор обязан утвердить фактический состав ролей, сроков, журналов и резервного копирования и только затем обновить опубликованные документы, если реальный процесс изменится.
