# Закрытая система управления персональными данными

## Статус

На Этапе 2 создан только серверный фундамент. Пользовательский интерфейс и внутренние API не введены в эксплуатацию. По умолчанию `PD_ADMIN_ENABLED=false`; Nginx дополнительно возвращает 404 для административных путей. Включать флаг до завершения Этапа 3 запрещено.

## Планируемые маршруты

- `/internal/personal-data/login`, `/internal/personal-data`;
- `leads`, `consents`, `access-log`, `subject-requests`, `legal-holds`;
- `incidents`, `exports`, `deletions`, `systems`, `legal-documents`;
- `users`, `settings`, `integrity`, `backups`;
- соответствующие API под `/api/internal/personal-data/**`.

Все страницы и API должны быть динамическими, `no-store`, `noindex`, без Метрики, CookieConsent, ИИ-инженера, внешних виджетов, рекламных пикселей и prefetch персональных URL. Авторизация, RBAC, CSRF, Origin и step-up проверяются на сервере при каждом чувствительном действии.

## Источник данных

Первичные JSON остаются техническим источником. Административная SQLite хранит только:

- HMAC точного телефона и e-mail с версией ключа;
- requestId, источник, даты, срок и технические статусы;
- служебный workflow и комментарии;
- аудит доступа, обращения, инциденты, legal hold;
- описания выгрузок, удаления, integrity и backup runs.

Имя, организация, телефон, e-mail, сообщение, диалог и файлы не дублируются в `lead_index`. Поиск по имени/организации на первом этапе — ограниченное серверное сканирование JSON с пагинацией, лимитом файлов и времени, разрешением `SEARCH_CONTACT` и записью события доступа.

## Безопасные ошибки

Клиент получает только утверждённый код (`AUTH_REQUIRED`, `PERMISSION_DENIED`, `CSRF_REJECTED`, `STEP_UP_REQUIRED`, `VALIDATION_ERROR`, `NOT_FOUND`, `CONFLICT`, `RATE_LIMITED`, `INTERNAL_ERROR`). Stack trace, абсолютные пути, SQL и содержание записей не возвращаются.

## Условия включения

1. Внешний порт 3000 закрыт и Next.js слушает только loopback.
2. Node.js `>=22.13.0` подтверждён.
3. Каталоги созданы с владельцем `nodejs` и правами `0700`; файлы — `0600`.
4. Все три независимых ключа имеют не менее 32 случайных байт.
5. Миграции, integrity и audit verify успешны.
6. Первый администратор создан вручную и сменил временный пароль.
7. Реализованы и протестированы страницы/API Этапа 3.
8. Nginx-блок Этапа 2 заменён только после отдельной проверки.
9. Юридические документы и внутренние локальные акты утверждены ответственным лицом.
