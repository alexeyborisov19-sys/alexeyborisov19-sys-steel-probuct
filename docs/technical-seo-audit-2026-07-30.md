# Технический SEO-аудит «Сталь Продукт»

Дата проверки: 30 июля 2026 года  
Основной адрес: `https://www.steelprodukt.ru`  
Проверяемая версия: локальная production-сборка, без публикации

## Итог

Локальная версия технически готова к публикации и последующей отправке на
переобход. Автоматический аудит проверяет 73 индексируемых URL из
`sitemap.xml` и завершается с результатом:

- ошибок: 0;
- предупреждений: 0;
- сборка Next.js: успешно;
- ESLint: успешно;
- TypeScript: успешно;
- тесты: 46 из 46 успешно.

Это подтверждает техническую готовность к обходу, но не означает, что страницы
уже проиндексированы или займут определённые позиции. Фактическая индексация
проверяется после публикации в Яндекс Вебмастере и Google Search Console.

Оценка технического SEO:

- опубликованная версия до локальной доработки: **6/10**;
- локальная версия после доработки: **9,3/10**;
- потенциальная оценка после публикации, переобхода и подтверждения полевых
  метрик: **до 9,7/10**.

Оценка 10/10 сейчас была бы недостоверной: отсутствуют свежие данные
Яндекс Вебмастера, Search Console и реальные Core Web Vitals пользователей
после публикации.

## 1. Что было найдено

### Высокий приоритет

1. В `robots.txt` одновременно использовались отдельная группа для Яндекса и
   общая группа `User-agent: *`. По документации Яндекса при наличии
   `User-agent: Yandex` общая группа игнорируется. Из-за этого правило
   `Disallow: /api/` из общей группы не действовало для Яндекса.
2. На странице семейства металлокассет отсутствовала специализированная
   микроразметка `ProductGroup`, связывающая четыре исполнения продукта.
3. API-маршруты не отдавали дополнительный заголовок
   `X-Robots-Tag: noindex, nofollow`.

### Средний приоритет

1. Одна новость не имела внутренней ссылки со страницы журнала и могла стать
   orphan page.
2. В подвале были ссылки на несуществующие фрагменты страницы компании.
3. Несколько интерфейсных и продуктовых изображений не имели явных
   `width`/`height`, режима декодирования или корректного приоритета загрузки.
   Это повышало риск сдвигов макета и неоптимального LCP.
4. Ссылка сайта в подвале и контактах сначала открывала домен без `www`, а затем
   проходила через постоянный редирект на канонический адрес.

### Внешняя инфраструктура

1. С опубликованного `http://steelprodukt.ru/...` наблюдается цепочка из двух
   редиректов: сначала на HTTPS без `www`, затем на HTTPS с `www`.
2. По одиночным сетевым замерам время ответа HTML опубликованной версии было
   примерно 0,75–0,81 секунды. Это не является Core Web Vitals, но показывает
   резерв для настройки Nginx, кэширования и серверного ответа.
3. Старая выдача поисковиков не может быть удалена только изменениями кода:
   после публикации нужен переобход и контроль исключённых/старых URL в
   кабинетах поисковых систем.

## 2. Что исправлено локально

### Robots и индексируемость

- `robots.txt` сведен к одной однозначной группе `User-agent: *`.
- Разрешён обход публичного сайта и запрещён обход `/api/`.
- Сохранены `Host`, основной sitemap, sitemap изображений и `Clean-param` для
  рекламных параметров.
- Для `/api/*` добавлен
  `X-Robots-Tag: noindex, nofollow, noarchive`.
- Проверено отсутствие случайных `noindex` и `nofollow` на всех 72 публичных
  страницах.
- Проверено отсутствие конфликта canonical/robots.

### Sitemap

- В `sitemap.xml` присутствуют 73 уникальных индексируемых URL.
- Каждый URL возвращает 200 в локальной production-сборке.
- Для каждого URL есть корректные `lastmod`, `changefreq` и `priority`.
- В sitemap нет удалённых API, 404 и 410 URL.
- Даты `lastmod` не находятся в будущем и не меняются автоматически при каждой
  сборке.
- Отдельный sitemap изображений возвращает 200 и содержит доступные изображения.
- Sitemap index не создавался: при 72 URL он не нужен. Ограничение одного
  sitemap — 50 000 URL или 50 МБ без сжатия.

### Canonical, дубли и редиректы

- У каждой индексируемой страницы есть абсолютный self-canonical на
  `https://www.steelprodukt.ru/...`.
- UTM, `gclid`, `yclid` и служебные параметры не меняют canonical.
- Проверены уникальность canonical и отсутствие canonical на другой
  индексируемый URL.
- Старый URL политической сводки имеет постоянный редирект на актуальную
  производственную публикацию.
- Удалённые страницы возвращают 410 и `noindex`, неизвестные URL — 404 и
  `noindex`.
- Внутренние ссылки не ведут через известные редиректы.

### Мета-теги и структура документов

- Проверены уникальные `title` и `description` всех 72 страниц.
- Проверены один H1 на страницу и логическая последовательность заголовков.
- Проверены `lang="ru"`, Open Graph, Twitter Cards, favicon и webmanifest.
- Проверена индексируемость страниц продуктов, решений, отраслей, производства
  и статей.

### Перелинковка

- Проверены внутренние ссылки между главной, производством, решениями,
  отраслями, продукцией, журналом и контактами.
- Убрана orphan page в разделе новостей.
- Исправлены ссылки подвала на существующие страницы и фрагменты.
- В статьях сохранены коммерческие ссылки на релевантные продукты, услуги и
  форму расчёта.
- Проверены битые ссылки и фрагменты: ошибок не найдено.

### Микроразметка JSON-LD

Проверены и используются:

- `Organization`;
- `LocalBusiness`;
- `Manufacturer`;
- `WebSite`;
- `WebPage`;
- `BreadcrumbList`;
- `Product`;
- `ProductGroup`;
- `Service`;
- `Article`;
- `FAQPage` там, где FAQ реально отображается;
- `ItemList` и `Event` для применимых списков.

В `Product` намеренно не добавлены вымышленные цена, наличие и рейтинг. Для
семейства металлокассет добавлена `ProductGroup` с реальными вариантами.

`SearchAction` намеренно не добавлен: у сайта нет публичного рабочего поиска,
поэтому такая разметка была бы недостоверной. Кроме того, Google прекратил
показывать sitelinks search box с 21 ноября 2024 года.

### Изображения и скорость

- Проверены доступность, MIME-типы и `alt` всех изображений.
- Для основных изображений заданы размеры, чтобы снизить риск CLS.
- Первый экран получает высокий приоритет загрузки; карточки ниже первого
  экрана загружаются лениво.
- Используются облегчённые WebP/JPEG-версии, а не исходные многомегабайтные
  файлы.
- Для статических изображений настроено длительное кэширование.
- Внешние шрифты не загружаются; используется системный стек, поэтому нет
  блокирующего запроса шрифта.
- Яндекс Метрика не инжектируется до явного согласия пользователя на аналитику.

Целевые полевые показатели:

- LCP: не более 2,5 секунды;
- INP: не более 200 мс;
- CLS: не более 0,1;
- оценка ведётся по 75-му процентилю отдельно для мобильных и настольных
  устройств.

Локальная сборка и размеры ресурсов проверены, но полевые Core Web Vitals можно
подтвердить только после публикации по данным реальных посетителей.

### Коммерческие факторы

На сайте присутствуют:

- телефон и электронная почта;
- юридический и производственный адреса;
- ИНН, КПП и ОГРН;
- реквизиты владельца сайта;
- формы заявки и загрузки документации;
- информация о производстве, оборудовании и технологических операциях;
- страницы продукции, решений и отраслей;
- политика обработки персональных данных и отдельные согласия.

Сертификаты и доказательства рекламных заявлений должны быть дополнительно
проверены владельцем бизнеса: технический аудит не может подтвердить
подлинность документов или производственных цифр.

## 3. Что невозможно исправить автоматически

1. Удалить старые сниппеты из выдачи без повторного обхода поисковыми роботами.
2. Подтвердить права на сайт в Яндекс Вебмастере и Search Console без доступа к
   соответствующим кабинетам.
3. Гарантировать срок индексации или позиции.
4. Подтвердить полевые LCP, INP и CLS до накопления данных реальных
   пользователей.
5. Подтвердить подлинность сертификатов, реквизитов и заявлений о возможностях
   производства.
6. Исправить цепочку HTTP-редиректов без изменения конфигурации Nginx на VPS.

## 4. Что нужно сделать вручную после публикации

### Сервер

1. Настроить один 301:
   `http://steelprodukt.ru/*` → `https://www.steelprodukt.ru/*`.
2. Проверить один 301:
   `http://www.steelprodukt.ru/*` → `https://www.steelprodukt.ru/*`.
3. Проверить постоянный редирект:
   `https://steelprodukt.ru/*` → `https://www.steelprodukt.ru/*`.
4. Проверить TLS для обоих доменных имён, HTTP/2 или HTTP/3, Brotli/Gzip и
   кэширование статики.
5. После публикации повторно запустить аудит против production URL.

### Яндекс Вебмастер

1. Подтвердить основной сайт `https://www.steelprodukt.ru`.
2. Добавить:
   - `https://www.steelprodukt.ru/sitemap.xml`;
   - `https://www.steelprodukt.ru/sitemap-images.xml`.
3. Проверить анализ `robots.txt` и Sitemap.
4. Запросить переобход приоритетных URL из следующего раздела.
5. Проверить «Индексирование → Страницы в поиске», исключённые URL,
   дубли, canonical и ответы сервера.
6. Проверить региональность и карточку организации в Яндекс Бизнесе.
7. Через 3–7 дней проверить факт обхода, через 2–4 недели — динамику покрытия.

### Google Search Console

1. Подтвердить доменное свойство или основной URL-prefix.
2. Отправить основной sitemap.
3. Проверить ключевые страницы инструментом проверки URL.
4. После накопления данных проверить отчёт Core Web Vitals.
