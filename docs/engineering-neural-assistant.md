# Локальная нейросеть для инженерных калькуляторов (Qwen 3.5)

## Что реализует этот релиз

Публичный инженерный помощник использует существующий серверный API `/api/assistant` и `/api/assistant/quote`. Он доступен по нажатию пользователя внутри:
- CAD-калькулятора `/online-order`;
- калькулятора металлокассет `/calculator-metallokassety`;
- подбора корзин кондиционеров `/products/korziny-dlya-konditsionerov`;
- двух BIM-инструментов (кассеты и Г-образные доборы).

Глобальная кнопка сайта теперь вызывает тот же инженерный помощник вместо ограниченного навигационного чат-бота. Контекст каждого инструмента содержит только подтверждённые публичные сведения. Помощник предлагает отредактировать вопрос **до** отправки, сам не читает CAD-файлы из браузера, не отправляет формулу цены или закрытые производственные данные.

**Нейросеть не является расчётным ядром.** CAD-геометрия, расчёты, цены, IFC, проверки допустимых полей и требования к чертежам остаются в существующих проверяемых алгоритмах. Результат расчёта без необходимых исходников не должен получать придуманную цену; проектные нагрузки, крепление и изготовляемость подтверждаются отдельно.

## Технология

Выбранный вариант для проверки: [Qwen 3.5 9B](https://huggingface.co/Qwen/Qwen3.5-9B) под Apache-2.0, через [Ollama](https://github.com/ollama/ollama) с тегом `qwen3.5:9b` ([официальный каталог](https://ollama.com/library/qwen3.5)).

В проекте **уже имеется** серверная интеграция с Ollama:
- Только фиксированный `http://127.0.0.1:11434`, никакого URL из браузера.
- Точное совпадение установленного тега и SHA-256 digest в `/api/tags`.
- Не допускаются remote/cloud-модели и псевдоним `:latest`.
- Сторонний контент отделён от системной инструкции; ответ строго в JSON и проверяется серверной схемой.
- Персональные идентификаторы вычищаются перед передачей модели, но это не заменяет запрета помещать конфиденциальные данные в публичный диалог.
- Внешняя платная модель не включается автоматически, ошибок локальной модели она не подменяет.
- При невозможности получить безопасный ответ — локальная справка с явным статусом «нейросеть не использовалась».

### До установки модели на Beget

1. Через доверенный доступ к VPS проверьте ОС, свободную память, дисковое пространство, CPU/GPU и загрузку других сервисов. **Не пытайтесь запускать 9B, если память сервера не позволяет это сделать без риска для сайта.** Скачиваемый файл модели около 6,6–7,6 ГБ; фактическое потребление RAM/VRAM и скорость зависят от ОС, контекста и квантования.
2. Сделайте резервную копию конфигурации, определите окно для испытаний и гарантированный способ отката. Сначала испытайте на отдельной машине или изолированном тестовом окружении. Не включайте модель на production-сервере без проверки свободных ресурсов и отказоустойчивости.
3. Установите Ollama по официальной инструкции, на уровне **демона** установите `OLLAMA_NO_CLOUD=1` и прослушивание только на `127.0.0.1:11434`. Не открывайте порт Ollama в Интернет. Перезапустите и проверьте **фактические** настройки процесса Ollama.
4. На тестовой машине отдельно загрузите зафиксированный релиз:
   ```bash
   ollama pull qwen3.5:9b
   ollama list
   curl --fail --silent --show-error http://127.0.0.1:11434/api/tags
   ```
   Сверьте полученный digest, название, `details.format=gguf` и отсутствие remote-полей в `/api/tags`. Не копируйте чужой digest из инструкции, это значение именно установленного артефакта.
5. В окружении **тестового** Next.js-процесса задайте:
   ```bash
   STEEL_PRODUCT_LOCAL_AI_ENABLED=true
   STEEL_PRODUCT_LOCAL_AI_MODEL=qwen3.5:9b
   STEEL_PRODUCT_LOCAL_AI_DIGEST=<64-символьный SHA-256 из локального /api/tags>
   STEEL_PRODUCT_LOCAL_AI_OFFLINE_VERIFIED=true
   STEEL_PRODUCT_LOCAL_AI_TIMEOUT_MS=45000
   STEEL_PRODUCT_PAID_SERVICES_ALLOWED=false
   YANDEX_AI_ENABLED=false
   ```
   `<...>` — документационный заполнитель, не реальное значение. Не сохраняйте секреты в Git. Значения в `.env.example` остаются выключенными до завершения испытаний.

### Проверки для допуска к публикации

- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` на точном SHA.
- В браузере на 390/1440 px проверить пять инженерных инструментов: фокус, Escape, отсутствие перекрытия мобильных действий, контраст и доступность.
- Убедиться, что открытие помощника **не** обращается к модели; отправка происходит только по нажатию пользователя.
- Проверить сообщение `mode: ai` при успешной генерации и `mode: knowledge` при выключенной Ollama, неверном digest, остановленном демоне, ошибке таймаута или некорректном JSON.
- Дважды сверить сохранность существующих CAD/BIM, IFC, корзины и базовой цены; нейросеть не может изменять их результаты.
- Нагрузочное испытание 1–2 одновременных запросов под реальными ресурсами VPS. В текущем серверном адаптере лимит активных локальных генераций — два.
- Проверить, что ключи, конфиденциальные CAD-файлы, исходные коммерческие цены и персональные данные отсутствуют в запросах модели, публичных логах и ответах.
- После допуска — настройка и ручная публикация согласно `DEPLOYMENT.md`. Сам факт merge **не устанавливает** веса Qwen или Ollama на VPS.

### Откат

Сначала выставить `STEEL_PRODUCT_LOCAL_AI_ENABLED=false` в серверном окружении и перезапустить только Next.js по утверждённому порядку. Генерация прекратится, справочный режим останется доступен. При необходимости откатить соответствующий PR после подтверждения целостности основного сайта. Нельзя удалять рабочие CAD-данные, тарифы, ПД или файлы клиента.

## Политика обучения только на общедоступных данных

В этом проекте под «обучением» понимаются проверенная подборка фактов, источник для каждого утверждения, системные правила и тесты типовых инженерных запросов. **Это не изменение весов Qwen и не дообучение на приватных данных.**

- Список допущенных URL и дата ручной сверки находятся в \`data/assistant-public-source-manifest.ts\`. Публичные сведения о компании сверены с открытыми страницами [Факты о производстве](https://www.steelprodukt.ru/company/facts), [О компании](https://www.steelprodukt.ru/company) и [Лазерная резка](https://www.steelprodukt.ru/production/lazernaya-rezka-metalla).
- Технические положения по \`$INSUNITS\` в DXF опираются на [официальный справочник Autodesk](https://help.autodesk.com/cloudhelp/2021/ENU/AutoCAD-DXF/files/GUID-A85E8E67-27CD-4C59-BE61-4DC9FADBE74A.htm), а сведения об IFC — на [официальную информацию buildingSMART](https://www.buildingsmart.org/standards/bsi-standards/industry-foundation-classes/?lang=en).
- Состав оборудования и масштабы — **публичные заявления самой компании**, не результат независимой инспекции. Для ассистента допустима формулировка «По опубликованным данным „Сталь Продукт“…», но не «ИИ проверил оборудование».
- Если справочная страница и текущий открытый код расходятся, спорный факт исключается из подтверждённой базы до сверки. Это особенно касается старого раздела BIM на странице \`/company/facts\`.
- Технические стандарты описывают формат и общие правила, **не подтверждают пригодность конкретного чертежа, геометрию, сертификат, допуски, нагрузки, технологию, срок или цену**.
- **Запрещено использовать для настройки, промптов, обучающих наборов и оценки:** документы закрытой CRM, персональные данные клиентов, почту и переписку, заявки, загруженные непубличные CAD/BIM-файлы, поставщиков и их коммерческие расценки, данные из \`.env\`, GitHub Secrets, не опубликованные внутренние отчёты, логи производственной эксплуатации и сведения из частных диалогов. Даже если такие данные доступны разработчику, они не являются общедоступными.
- Результаты диагностики Beget — сведения о ресурсах инфраструктуры и **не передаются в контекст нейросети**. Диагностика не запускает модель и не загружает веса.
- Автотесты \`tests/assistant-public-sources.test.ts\` и \`tests/assistant-verified-curriculum.test.ts\` контролируют источники, соответствие каноническим данным, отсутствие приватных сведений и инженерные ограничения. Реальные ответы Qwen нужно отдельно испытать после развёртывания в **ресурсно достаточной изолированной среде**.

## Что пока не реализовано

Модель не читает напрямую CAD/STEP/DWG, не конструирует новые 3D-детали по свободному запросу и не подтверждает прочность/изготовляемость без отдельной валидируемой CAD/DFM-процедуры. Для этой функции нужен следующий изолированный этап с валидацией геометрии, правами доступа и ручным утверждением исправлений. Этот релиз улучшает нейросетевой диалог и связывает его с существующими калькуляторами, **но не превращает GPT-подобную модель в самостоятельный CAD-движок**.
