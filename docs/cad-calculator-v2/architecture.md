# Архитектура выпуска

Сайт и локальное приложение используют одно происхождение расчётного ядра. Клиентское состояние не устанавливает геометрию или цену: оригинальные байты повторно проверяются сервером. Изменение конфигурации отменяет старый запрос; удаление файла/открытие проекта отменяет его анализ.

Публичная композиция отделена от ProductionApplication. Производственные маршруты не входят в публичный выпуск. Локальный сервер привязан к loopback и точному Host, авторизация и CSRF проверяются на сервере. Черновики хранятся вне public, раздельно по пользователям, атомарно, оригиналы 0600, каталоги 0700. Каждый save — новый идентификатор; восстановление не восстанавливает старую сумму.

Отчёт калькуляции неизменяем, содержит фактические статьи и версию базы; технологическая правка создаёт ревизию. Экономика читает отчёт текущего calculationId, при изменении проекта старый отчёт не отображается как текущий. CSV спецификации/маршрута содержит только текущую конфигурацию, опасные начальные символы экранируются для табличных редакторов.

Раскладка: bounded deterministic shelf packing прямоугольных заготовок, группы материал+толщина, явные поля/зазор/разрешение поворота. До 1000 экземпляров; площадь листов = площадь заготовок + незанятая площадь. Схема не влияет на себестоимость без утверждённого метода распределения и не считается контурной оптимизацией.

ИИ — отдельная дополнительная стадия с pin модели и digest, только localhost, OLLAMA_NO_CLOUD=1. JSON проходит схему и семантический валидатор; ошибки, недоступность или таймаут не создают фиктивное подтверждение. Расчётная арифметика и DFM имеют приоритет.
