# Обращения субъектов персональных данных

## Workflow

`RECEIVED → IDENTITY_REQUIRED/IDENTITY_VERIFICATION → IN_PROGRESS → RESPONSE_PREPARED → APPROVAL_REQUIRED → COMPLETED/CLOSED`.

`REJECTED_WITH_REASON` требует мотивировки. `EXTENDED` сохраняет исходный `due_at` и добавляет отдельное событие истории, не переписывая первоначальный срок.

## Идентификация

Поддерживаются подтверждение через ранее указанные e-mail/телефон, requestId, договор, личный документ, подписанное электронное обращение или иной утверждённый способ. Выбор способа не означает автоматического подтверждения. Полная копия паспорта по умолчанию не собирается.

Статусы: `NOT_STARTED`, `ADDITIONAL_INFORMATION_REQUIRED`, `VERIFIED`, `FAILED`, `NOT_REQUIRED`. Подготовка официальной выгрузки типа `SUBJECT_REQUEST` доступна только для `VERIFIED` или документированного `NOT_REQUIRED`.

## Сроки

Для доступа и сведений технический срок рассчитывается как 10 рабочих дней; для уточнения/уничтожения по подтверждающим сведениям — 7 рабочих дней; отзыв согласия получает отдельный 30-дневный ориентир. Продление доступа/сведений ограничено пятью рабочими днями и требует мотивировки. Ответственный обязан сверить специальные сроки и производственный календарь вручную.

## Аудит

Фиксируются создание, проверка личности, изменение, продление, завершение и мотивированный отказ. Открытый запрос блокирует плановое удаление связанной заявки. Полные контакты не помещаются в технический access log.
