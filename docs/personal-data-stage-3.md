# Этап 3: закрытая административная система

## Статус

Реализация подготовлена локально в ветке `feat/personal-data-stage-3`. Push, merge, production-миграции, production ADMIN и включение `PD_ADMIN_ENABLED` не выполнялись. Первичные заявки, consent-audit и карантин не изменялись.

## Реализовано

- изолированный App Router layout без Header, Footer, Метрики, CookieConsent, ИИ-инженера, preloader и внешних виджетов;
- одинаковый 404 для всех internal pages/API при `PD_ADMIN_ENABLED=false`;
- вход по личной учётной записи, pre-auth challenge, persistent rate limit/lock, versioned scrypt;
- серверные hash-only сессии, idle/absolute timeout, CSRF, Origin, User-Agent binding, logout/rotation/step-up;
- централизованная RBAC-матрица четырёх ролей;
- dashboard без открытых ПДн;
- маскированный реестр, поиск requestId, versioned HMAC-поиск контактов и bounded text search;
- карточка заявки, раскрытие по основанию, workflow, назначение, добавление и редактирование собственного комментария, метаданные и безопасное скачивание вложений;
- продление и снятие служебного срока хранения только после step-up, с единым атомарным событием аудита;
- просмотр consent-audit;
- журнал доступа и проверка HMAC-цепочки;
- integrity runs;
- управление пользователями и сессиями с step-up и защитой последнего ADMIN;
- запрет автоматических миграций из HTTP-запросов: схема меняется только отдельной командой `pd:migrate`;
- безопасные заглушки модулей следующего этапа без фиктивных форм и записей.

## Не реализовано намеренно

Обращения субъектов, официальный export wizard, фактическое удаление, инциденты, реестры систем/подрядчиков, управление версиями юридических документов и независимое внешнее резервное копирование относятся к следующему этапу. Legacy cleanup `--apply` запускать запрещено.

## Production activation runbook

До отдельного подтверждения действия ниже не выполнять.

1. Убедиться, что рабочая версия сайта не содержит незапланированных изменений и все проверки успешны.
2. Оставить `PD_ADMIN_ENABLED=false`, обновить код и собрать приложение.
3. Проверить loopback: `ss -lntp | grep ':3000'` должен показывать только `127.0.0.1:3000`; внешний TCP/3000 и TCP/3011 должен оставаться закрытым.
4. Проверить владельца/права `/var/lib/steelprodukt/admin` и `/var/lib/steelprodukt/exports`: `nodejs`, каталоги `0700`; не читать и не печатать секреты.
5. Выполнить `npm run env:check`, `npm run pd:migrate:status`, затем вручную `npm run pd:migrate`.
6. Выполнить `npm run pd:integrity-check`, `npm run pd:audit-verify` и dry-run `npm run pd:sync-index -- --dry-run`.
7. Создать первого ADMIN вручную через `npm run pd:create-admin`; пароль вводится скрыто через stdin и не передаётся аргументом.
8. Применить проверенную Nginx-конфигурацию, проверить `nginx -t`, затем reload. При выключенном флаге страницы и API обязаны по-прежнему возвращать 404.
9. Только после проверки включить `PD_ADMIN_ENABLED=true`, выполнить production build и `pm2 restart steelprodukt --update-env`. Internal-запросы должны подтверждать канонический HTTPS reverse proxy; прямой HTTP отклоняется.
10. Проверить login, обязательную смену пароля, роли, CSRF, no-store/noindex/CSP, журнал входа и отсутствие маркетинговых запросов в Network.
11. Выполнить индексирование dry-run, затем incremental только после просмотра отчёта без открытых контактов.
12. Проверить публичные `/api/quote` и `/api/assistant/lead`: при недоступной administrative SQLite они обязаны продолжить первичное JSON-сохранение.

## Rollback

1. Установить `PD_ADMIN_ENABLED=false` и пересобрать приложение.
2. Перезапустить PM2 с `--update-env`.
3. Убедиться, что internal pages/API возвращают 404, публичный сайт и формы работают.
4. Не удалять SQLite и первичные файлы. Для отката кода использовать предыдущий проверенный release/commit обычным deployment-механизмом.
5. Не восстанавливать backup поверх production без отдельного подтверждения и изолированной проверки.

## Резервное копирование

Текущий общий статус: **частичная готовность**. Локальная зашифрованная копия на том же VPS проверена восстановлением 23 файлов, но независимая внешняя российская копия отсутствует. Не отображать этот статус как полностью готовый.

## Юридические документы

Пока система не включена, публичное утверждение «не введена в эксплуатацию» остаётся правильным. Перед включением ответственный сотрудник должен сопоставить фактические роли, операции, сроки и backup с политикой, реестром и локальными актами; изменения публикуются только после юридического утверждения.
