# Предпродакшен-приёмка контура персональных данных

## Статус

Код подготовлен локально в ветке `release/personal-data-preproduction`.
Production не мигрирован, `PD_ADMIN_ENABLED=false`, первый production ADMIN не
создан, реальные заявки не индексировались и не удалялись.

## Принятый минимальный объём

Оператор не подключает второй backup-провайдер, VPN или Nginx Basic Auth без
отдельного решения. Действующий обязательный контур включает:

- Next.js только на loopback, закрытые внешние порты и Nginx;
- персональные учётные записи, RBAC, CSRF, Origin и step-up;
- закрытые каталоги `0700`, файлы `0600` и отсутствие ПДн в `public`;
- зашифрованную off-server копию в Beget Object Storage с SHA-256, сроком
  хранения и проверенным обратным чтением;
- разграниченные сроки хранения, legal hold, контролируемое удаление и аудит;
- Gitleaks для полной Git-истории и рабочего дерева;
- ручное подтверждение юридических сроков ответственным сотрудником;
- утверждение локальных актов до включения кабинета.

VPS и Object Storage находятся в одном аккаунте Beget. Это документированный
остаточный риск единого провайдера, но второй поставщик не является текущим
автоматическим блокером. Решение пересматривается при изменении модели угроз,
объёма данных или утверждённых локальных актов.

## Условия допуска к миграции

- `npm run secrets:scan`, тесты, build и dependency audit проходят;
- текущая backup и restore-test подтверждены фактическими отчётами;
- ответственный за обработку ПДн и руководитель утвердили применимые документы;
- срок каждого нового обращения подтверждает человек, а технический расчёт
  хранится отдельно;
- timer удаления временных экспортов сначала проходит `--dry-run`;
- fixture-приёмка не использует реальные данные;
- runbook миграции и rollback проверены ответственными;
- до отдельного решения `PD_ADMIN_ENABLED=false`.

Документ не заменяет заключение российского юриста и не утверждает локальные
акты автоматически.
