# Модуль «КП → заявка в производство → папка заказа → Bitrix24»

Статус: отдельное внедрение в Draft PR #173. Рабочий CAD-калькулятор, `main` и production не меняются.

## Рабочий маршрут

1. Внутренний CAD-калькулятор завершает расчёт и сохраняет конфиденциальный производственный отчёт.
2. Менеджер открывает `/internal/production-order` и выбирает расчёт.
3. В редакторе указывает номер КП, название КП, заказчика, сроки, приоритет и ответственного.
4. При необходимости корректирует только разрешённые поля позиции: наименование, количество и примечание цеху.
5. Сервер заново восстанавливает материал, геометрию, операции, цену и ссылки на исходные CAD-файлы из защищённого отчёта. Клиентский браузер не может подменить эти поля.
6. Сервер создаёт папку `<номер КП> <название КП>` внутри сохранённой корневой папки заказов.
7. В корень папки записываются:
   - `КП <номер>.pdf`;
   - `Заявка в производство <номер>.pdf`;
   - `order-manifest.json`;
   - `order-journal.jsonl`.
8. Исходные файлы из защищённого quarantine-хранилища копируются в реально используемые подпапки: `CAD`, `Чертежи`, `Вложения`.
9. Каждое фактическое изменение создаёт каталог `Ревизии/0001`, `Ревизии/0002` и далее. Повторный вызов без изменений новую ревизию не создаёт.
10. Кнопка «Создать заявку в Bitrix24» создаёт сделку в заданных воронке и стадии. Повторный вызов обновляет ту же сделку по `ORIGIN_ID`, а не создаёт дубль.

## Рабочие страницы

- `/internal/production-order` — выбор зафиксированного производственного расчёта;
- `/internal/production-order/from-calculation/<fileName>` — редактор КП и производственной заявки;
- `/internal/production-order/settings` — выбор и сохранение корневой папки заказов.

## Настройка папки заказов

На странице настройки доступны:

- ручной ввод абсолютного пути;
- кнопка `Обзор`, открывающая системный выбор папки на компьютере, где запущен Next.js-калькулятор;
- проверка существования папки и реальной возможности создать и удалить тестовый файл;
- сохранение выбранного пути после перезапуска приложения.

Сохранённое значение записывается в закрытый файл:

`<STEEL_PRODUCT_PRIVATE_SETTINGS_ROOT или ~/.steelprodukt>/production-order-storage.json`

Сохранённый через интерфейс путь имеет приоритет над `STEEL_PRODUCT_ORDER_ROOT`. Переменная окружения остаётся резервным вариантом.

Важно: системное окно `Обзор` открывается на компьютере, где выполняется сервер приложения. При удалённом размещении путь вводится вручную либо удалённый вызов явно разрешается настройкой.

## Формирование документов

Endpoint:

`POST /api/internal/production-order/package`

Он:

- принимает заявку после строгой проверки структуры;
- находит последний защищённый производственный отчёт по неизменяемому `projectId`;
- восстанавливает технические данные и цены из серверного отчёта;
- создаёт или обновляет папку заказа без дублей;
- копирует доступные STEP, STP, DXF и DWG из защищённого quarantine-хранилища;
- создаёт PDF коммерческого предложения;
- создаёт PDF производственной заявки в светлом печатном дизайне без логотипа и тёмных заливок;
- сохраняет текущие документы в корень папки и их копии в каталог ревизии;
- записывает результат каждого шага в `order-journal.jsonl`;
- при отсутствии браузера сохраняет папку, манифест и исходные файлы, а в интерфейсе возвращает понятное предупреждение о невозможности создать PDF.

Для PDF используется установленный Chrome, Microsoft Edge или Chromium в headless-режиме. Путь к нестандартной установке задаётся через `STEEL_PRODUCT_PDF_BROWSER_PATH`.

## Bitrix24

Endpoint:

`POST /api/internal/production-order/bitrix`

Перед отправкой данные также заново восстанавливаются из защищённого производственного отчёта. Сделка получает:

- номер и название КП;
- заказчика;
- количество позиций;
- срок готовности;
- сумму КП, когда она подтверждена расчётом;
- путь к папке заказа;
- заданные `CATEGORY_ID` и `STAGE_ID`;
- стабильные `ORIGINATOR_ID` и `ORIGIN_ID` для защиты от дублей.

Коды пользовательских полей портала не угадываются и задаются только через `BITRIX_ORDER_FIELD_MAP_JSON`.

## Защита и ограничения

- до 50 деталей в одной заявке;
- файловый корень находится вне `public/`;
- выбранная папка должна существовать и быть доступна процессу Node.js для записи;
- реальные пути quarantine-хранилища не передаются в браузер;
- имена и источники файлов проверяются сервером;
- клиент не может подменить материал, геометрию, операции, цену или источник CAD-файла;
- изменение количества автоматически делает прежнюю цену недействительной;
- папка другого заказа или заполненная посторонняя папка не перезаписывается;
- Bitrix webhook хранится только в серверных переменных окружения;
- печатная заявка не показывает внутренние ставки и себестоимость;
- пустые разделы файлов, доставки и операций не выводятся;
- старые расчёты без полного input snapshot или без сохранённых файловых ссылок требуют повторного расчёта CAD.

## Переменные окружения

```text
# Резервный путь, если путь ещё не сохранён через интерфейс
STEEL_PRODUCT_ORDER_ROOT=\\\\SERVER\\Production\\Orders

# Необязательно: отдельное место для закрытого файла настроек
STEEL_PRODUCT_PRIVATE_SETTINGS_ROOT=/private/app-settings

# По умолчанию системный обзор разрешён только через localhost
STEEL_PRODUCT_NATIVE_FOLDER_PICKER_ALLOW_REMOTE=false

# Необязательно: нестандартный путь к Chrome / Edge / Chromium
STEEL_PRODUCT_PDF_BROWSER_PATH=/Applications/Google Chrome.app/Contents/MacOS/Google Chrome

# Только для изолированного Linux-контейнера, если запуск браузера иначе невозможен
STEEL_PRODUCT_PDF_NO_SANDBOX=false

BITRIX_ORDER_INTEGRATION_ENABLED=true
BITRIX_WEBHOOK_URL=https://<portal>.bitrix24.ru/rest/<user>/<token>
BITRIX_ORDER_CATEGORY_ID=<numeric category id>
BITRIX_ORDER_STAGE_ID=<stage id>
BITRIX_ORDER_FIELD_MAP_JSON={"quoteNumber":"UF_CRM_...","orderFolder":"UF_CRM_...","dueDate":"UF_CRM_...","projectId":"UF_CRM_...","partsCount":"UF_CRM_..."}
```

## Реализовано в PR #173

- модель производственной заявки и коммерческих данных;
- адаптер расчёт → `ProductionOrder` до 50 деталей;
- строгая серверная проверка заявки;
- серверное восстановление неизменяемых данных из производственного отчёта;
- редактор основных полей и позиций;
- печатная форма и автоматическая генерация двух PDF;
- автоматическое копирование исходных CAD-файлов;
- безопасные имена папок и файлов;
- сохранение корневого пути через интерфейс;
- системный обзор папок для macOS, Windows и Linux с `zenity`;
- проверка прав на запись;
- повторяемое создание папки заказа без дублей;
- numbered revisions и append-only журнал операций;
- создание и обновление сделки Bitrix24;
- тесты для 1–50 деталей, путей, ревизий, PDF-шаблонов, quarantine-файлов, Bitrix24 и защиты от подмены данных.

## Что остаётся перед объединением

1. проверить реальный пользовательский сценарий на `localhost:3140` с настоящими STEP/DXF-файлами;
2. проверить автоматическую генерацию PDF установленным браузером на рабочем компьютере;
3. указать фактические `BITRIX_ORDER_CATEGORY_ID` и `BITRIX_ORDER_STAGE_ID`;
4. проверить создание и повторное обновление тестовой сделки Bitrix24;
5. после отдельного подтверждения подключить вход в модуль непосредственно к `/internal/production-calculator`;
6. только после этого рассматривать снятие Draft и объединение PR.
