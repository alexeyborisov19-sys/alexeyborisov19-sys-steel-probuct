# Чек-лист публикации и индексации

Локальный SEO-аудит подтверждает готовность к публикации, но не означает, что
страницы уже находятся в индексе. Фактический статус проверяется только в
Яндекс Вебмастере, Google Search Console и логах production-сервера.

## До переключения домена

- DNS `A` для `steelprodukt.ru` и `www.steelprodukt.ru` указывает на актуальный VPS.
- Node.js слушает только `127.0.0.1:3000`; наружу открыты Nginx `80/443`.
- Установлен действующий TLS-сертификат для обоих имён.
- `http://` и домен без `www` дают один 301 на
  `https://www.steelprodukt.ru`.
- PM2 запускает правильный каталог и сохраняет процесс после перезагрузки.
- В production заданы `NEXT_PUBLIC_SITE_URL=https://www.steelprodukt.ru` и
  идентификаторы подтверждения поисковых кабинетов.

## После запуска

- `/robots.txt`, `/sitemap.xml`, `/sitemap-images.xml`, `/feed.xml`,
  `/llms.txt`, `/llms-full.txt` возвращают 200.
- Все URL из sitemap возвращают 200 и canonical на `www`.
- Старые релевантные URL дают 301, окончательно удалённые — 410.
- Нет случайных `noindex`, циклических редиректов и дублей со слешем.
- Блокирующий CSP, формы, изображения и Метрика после согласия проверены в
  браузере. После подключения любого нового внешнего ресурса CSP проверяется
  повторно до публикации.

## Яндекс Вебмастер

- Подтвердить `https://www.steelprodukt.ru`.
- Отправить `https://www.steelprodukt.ru/sitemap.xml` и
  `https://www.steelprodukt.ru/sitemap-images.xml`.
- Запросить переобход главной, `/production`, `/products`, `/solutions`,
  `/industries`, `/articles`, `/contacts` и ключевых карточек.
- Проверить «Диагностика», исключённые страницы, canonical и ответы сервера.
- Проверять логи Nginx по User-Agent Яндекса и реальные коды ответа.
- Не создавать отдельную группу `User-agent: Yandex`, если её правила не
  дублируют полностью необходимые правила общей группы: при наличии такой
  группы Яндекс игнорирует `User-agent: *`.

## Google Search Console

- Подтвердить доменное свойство или URL-prefix для основного `www`-адреса.
- Отправить sitemap и проверить ключевые URL инструментом проверки страниц.
- Не заявлять об индексации до появления данных в кабинете.

## Наблюдение

- Через 3–7 дней проверить обход, через 2–4 недели — изменение покрытия.
- Не менять `lastmod` при каждой сборке: дата меняется только при фактическом
  содержательном обновлении страницы.
- Публиковать новые статьи с внутренними ссылками на соответствующие продукты,
  отрасли и форму расчёта.
- Sitemap index пока не нужен: основной sitemap содержит 72 URL, что далеко от
  лимита 50 000 URL или 50 МБ.
- Не добавлять фиктивный `SearchAction`, пока на сайте нет реального публичного
  поиска. Недостоверная микроразметка не улучшает индексацию.
- Полный локальный отчёт перед публикацией:
  `docs/technical-seo-audit-2026-07-30.md`.
