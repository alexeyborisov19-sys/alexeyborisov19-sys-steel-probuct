# План production-приёмки на синтетических данных

Fixtures создаются только в отдельном временном root и отдельной SQLite. Они не
помещаются в `quote-leads`, `assistant-leads`, `consent-audit` или quarantine
реальных клиентов.

## Изоляция

- отдельные `PD_ADMIN_DB_PATH`, `PD_EXPORT_PATH`, lead/consent/quarantine roots;
- отдельные случайные тестовые ключи, созданные на сервере и удалённые после
  проверки;
- каталоги `0700`, файлы `0600`, отсутствие symlink в production roots;
- адреса только домена `.invalid`, вымышленные имена и технические тексты;
- fixture ID имеют однозначную маркировку в изолированной базе.

## Сценарий

Проверить роли, маскирование, поиск, consent, clean/blocked attachment, legal
hold, выборочный экспорт, скачивание, TTL dry-run/apply, deletion dry-run,
контролируемое удаление только fixture, verify, акт и инцидент. После проверки
удалить временный незашифрованный fixture-root; отчёт хранит только количества,
коды и SHA-256 без контактов и содержимого.

Запрещено тестировать физическое удаление, symlink или повреждение JSON внутри
production-хранилища клиентов.
