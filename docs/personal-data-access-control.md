# Управление доступом

## Авторизация

- индивидуальная учётная запись;
- versioned scrypt и индивидуальная соль;
- случайный 256-битный session token, в SQLite только HMAC;
- cookie `__Host-steelprodukt-pd-session`: HttpOnly, Secure, SameSite=Strict, Path=/, без Domain;
- idle и absolute timeout, отзыв одной/всех сессий;
- блокировка учётной записи и временная блокировка источника после неудачных входов;
- обязательная смена временного пароля;
- Origin + Fetch Metadata + CSRF token для mutation;
- step-up перед экспортом, скачиванием официального ZIP, удалением, ролями, деактивацией, снятием legal hold и изменением хранения.

MFA не реализована на Этапе 2 и остаётся обязательным усилением до широкого доступа.

## Аудит

Чувствительные действия вызывают `recordAccessEvent()`. Разрешены только технические метаданные из whitelist: внутренние идентификаторы, роль, количество, размер, статус, код и основание. Открытые контакты, сообщения, комментарии и пути запрещены.

Цепочка HMAC позволяет обнаружить изменение известных записей, но не является абсолютной неизменяемостью. Доступ к БД и `PD_AUDIT_CHAIN_KEY` должен быть разделён, а проверочный checkpoint — храниться отдельно.
