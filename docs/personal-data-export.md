# Официальная выгрузка персональных данных

## Статус

На Этапе 4 worker, ZIP/XLSX/CSV/JSON и защищённый UI реализованы локально на fixture-данных. Production не изменён, worker и TTL scheduler там не запускались.

## Состояния

`DRAFT → PREVIEW_READY → APPROVAL_REQUIRED → BUILDING → READY → DOWNLOADED → TRANSFERRED/EXPIRED → DELETED`, при ошибке — `FAILED`.

## Процесс

1. Уполномоченный сотрудник указывает основание и ограниченный фильтр.
2. Preview перечисляет категории, количества и объём без копирования файлов.
3. Пользователь проходит step-up.
4. Второе полномочное лицо подтверждает состав, когда это предусмотрено регламентом.
5. На выбранные заявки ставится `EXPORT` lock.
6. Worker без `shell=true` создаёт архив вне `public`.
7. В архив входят только выбранные JSON, consent-audit, разрешённые вложения, связанные журналы, опись, README, `export_metadata.json`, таблица и `SHA256SUMS.txt`.
8. Ячейки CSV/XLSX, начинающиеся с `=`, `+`, `-`, `@`, нейтрализуются.
9. SHA-256 готового ZIP сохраняется только в `exports.archive_sha256`, защищённой странице и access event.
10. Скачивание требует step-up и журналируется; постоянный публичный URL не создаётся.
11. Передача выполняется человеком и фиксируется отдельно.
12. После TTL ZIP удаляется, а хеши, история скачиваний и передачи остаются.

Финальный хеш ZIP нельзя поместить внутрь этого же ZIP: изменение внутреннего файла меняет архив и его хеш. `manifest.json` описывает payload-файлы; `SHA256SUMS.txt` содержит суммы всех включённых файлов, кроме самого `SHA256SUMS.txt`; финальный SHA-256 ZIP хранится только вне архива.

Утверждённый preview фиксирует набор `requestId`. Новая запись, совпавшая с исходным фильтром после approval, не попадёт в ZIP без нового preview. Создатель и утверждающий предпочтительно различаются; self-approval допустим только для назначенного утверждающего и явно сохраняется.

XLSX не содержит формул. Любые внешние значения, начинающиеся с `=`, `+`, `-` или `@`, получают безопасный текстовый префикс. Клиентские значения не передаются в shell.

## Запреты

- пустой фильтр и неограниченный «экспорт всего»;
- пользовательские данные в shell-команде;
- отправка ZIP по e-mail;
- включение blocked-файла;
- логирование содержания, имён исходных файлов или абсолютных путей;
- экспорт одновременно с удалением той же заявки.

## Эксплуатация

Команда `npm run pd:exports:expire` должна запускаться отдельным контролируемым планировщиком от пользователя приложения. До его настройки нельзя считать TTL автоматическим на production. Истёкший файл недоступен даже до физической очистки; каждое скачивание требует active step-up и журналируется.
