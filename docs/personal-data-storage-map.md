# Карта хранения персональных данных и журналов

## Фактически действующее хранение

| Категория | Путь | Содержание | Доступ | Основной источник |
|---|---|---|---|---|
| Заявки формы | `/var/lib/steelprodukt/quote-leads` | JSON обращения, контакты, технические поля | пользователь приложения, уполномоченные сотрудники | Да |
| Заявки ИИ-инженера | `/var/lib/steelprodukt/assistant-leads` | JSON технической сводки и контактов | то же | Да |
| Вложения | `/var/lib/steelprodukt/quarantine` | пользовательские файлы и результат проверки | то же | Да |
| Доказательства согласия | `/var/lib/steelprodukt/consent-audit` | версии документов, время, requestId, хешированные контакты/сеть | то же | Да, отдельный срок |
| PM2 | конфигурация сервера | обезличенные route/result/code/ipHash/requestId | администратор VPS | Нет, технический журнал |

Фактические права и владелец production должны быть подтверждены на VPS; код и документация сами по себе этого не доказывают.

## Архитектурно подготовлено, но не включено

| Категория | Путь | Содержание | Статус |
|---|---|---|---|
| Служебная SQLite | `/var/lib/steelprodukt/admin/personal-data.sqlite` | метаданные, HMAC-индексы, роли, аудит, workflow | выключено |
| Временные выгрузки | `/var/lib/steelprodukt/exports` | официальные архивы с TTL | pipeline не реализован |
| Backup | `PD_BACKUP_PATH` | зашифрованные резервные копии | только проект |

SQLite не содержит секретов. `PD_SEARCH_HMAC_KEY`, `PD_SESSION_HASH_KEY`, `PD_AUDIT_CHAIN_KEY` и ключ backup находятся только в защищённом production environment/файле ключа.

## Инварианты

- пути находятся вне `public`, `.next` и deployment-sync;
- абсолютный путь от браузера никогда не принимается;
- symlink блокируется;
- каталоги `0700`, файлы `0600`;
- полные контакты не попадают в CLI output, access-event metadata или отчёты integrity;
- удаление первичных данных не выполняется одной SQLite-транзакцией: требуется lock, файловая операция, verify и акт.
