# Контролируемое уничтожение персональных данных

## Процесс

`SCAN → CANDIDATES → POLICY_CHECK → HUMAN_APPROVAL → LOCK → DELETE → VERIFY → REPORT → ACT → AUDIT`.

Режим по умолчанию — `DRY_RUN`. Approval и execution требуют отдельных permissions и active step-up. Система сохраняет, совпадает ли создатель scan и утверждающий. До approval физические файлы не меняются.

## Безопасность пути

Клиент не передаёт filesystem path. Worker берёт путь только из известной связи, проверяет разрешённый root, `realpath/lstat`, обычный файл и запрет symlink. Удаление перечисляет каждую категорию явно. При расхождении операция получает partial/failed, после чего verify обязан обнаружить остаток.

Не удаляются access audit, история requests/holds/incidents/exports/deletions и consent-audit до его собственного срока.

## Подтверждение уничтожения

После успешного verify создаются служебный отчёт и DOCX-акт с контрольными суммами. Для автоматизированной обработки акт должен использоваться вместе с предусмотренной приказом Роскомнадзора № 179 выгрузкой из журнала событий. Проект хранит доказательства и историю; утверждение/подписание выполняются человеком по локальному акту оператора.

Документы об уничтожении следует хранить установленный нормативным и локальным актом срок; текущий ориентир приказа № 179 — три года с момента уничтожения. Перед production этот срок должен быть закреплён в retention policy.
