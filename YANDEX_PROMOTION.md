# Продвижение SteelProdukt только в Яндексе

Этот сайт уже подготовлен для органической выдачи Яндекса: у него есть канонические URL, `robots.txt`, XML-карта сайта, JSON-LD-разметка компании, продукции, услуг, FAQ и хлебных крошек. В коде отключена Google Analytics — для измерения используется только Яндекс Метрика.

## Что необходимо подключить один раз

1. В [Яндекс Вебмастере](https://webmaster.yandex.ru/) добавьте сайт `https://www.steelprodukt.ru/` и подтвердите права на домен. Выберите способ «мета-тег».
2. Из мета-тега скопируйте только значение `content` и добавьте его на сервер как переменную `NEXT_PUBLIC_YANDEX_VERIFICATION`. Затем выполните сборку и перезапуск сайта.
3. В Вебмастере добавьте две карты: `https://www.steelprodukt.ru/sitemap.xml` и `https://www.steelprodukt.ru/sitemap-images.xml`. Проверить доступность робота можно по адресу `https://www.steelprodukt.ru/robots.txt`.
4. В [Яндекс Метрике](https://metrika.yandex.ru/) создайте счётчик для `https://www.steelprodukt.ru/`, включите «Вебвизор», «Карта кликов», «Отслеживание ссылок» и «Точный показатель отказов».
5. Добавьте номер счётчика на сервер как переменную `NEXT_PUBLIC_YM_COUNTER_ID` и перезапустите приложение. До добавления номера Метрика намеренно не подключается.
6. Вебвизор включается **двумя** настройками. Галочки в интерфейсе Метрики недостаточно: счётчик инициализируется с параметром `webvisor` из переменной окружения, и по умолчанию она выключена. Чтобы записи сеансов появились, задайте на сервере `NEXT_PUBLIC_YM_WEBVISOR=true` и перезапустите приложение. Учтите, что Вебвизор пишет содержимое страниц, поэтому включайте его осознанно — на страницах с формами это персональные данные.

Счётчик загружается только после согласия посетителя на аналитические cookie. Пока согласие не дано, запросов к Метрике нет вовсе, и часть трафика в отчёты не попадёт — это осознанное требование 152-ФЗ, а не ошибка настройки.

## Цели для B2B-воронки

Создайте в Метрике JavaScript-события с точными идентификаторами:

| Цель | Идентификатор | Когда фиксируется |
| --- | --- | --- |
| Открыта форма расчёта | `ym-open-leadform` | Посетитель начал заполнять форму |
| Открыта форма (детализация) | `quote_form_started` | Дублирующая бизнес-цель для отчётов |
| Прикреплён файл | `quote_file_attached` | Добавлен PDF, DXF, DWG или другой файл |
| Отправлена заявка | `ym-submit-leadform` | Сервер успешно принял заявку |
| Заявка отправлена (детализация) | `quote_request_success` | Дублирующая бизнес-цель для отчётов |
| Клик по e-mail | `ym-show-contacts` | Посетитель открывает контактный e-mail |
| Клик по e-mail (детализация) | `email_click` | Дублирующая бизнес-цель для отчётов |
| Скачан каталог | `catalog_download` | Скачан каталог продукции |

В качестве основной конверсии Яндекс Директа и РСЯ используйте только `ym-submit-leadform`: она срабатывает после успешного ответа сайта, а не после простого нажатия кнопки.

Код отправляет ещё несколько событий той же воронки. Цели с этими идентификаторами создавать
необязательно, но без них данные просто теряются: Метрика молча игнорирует `reachGoal` для
несуществующей цели.

| Идентификатор | Когда фиксируется |
| --- | --- |
| `quote_request_submit` | Форма отправлена, ответ сервера ещё не получен |
| `quote_request_error` | Сервер отклонил заявку — расхождение с `quote_request_success` показывает сломанную форму |
| `quote_files_cta_click` | Клик по призыву приложить файлы |
| `exhibition_official_click` | Переход на официальный сайт выставки |
| `exhibition_quote_click` | Запрос расчёта со страницы выставки |
| `assistant_opened` | Открыт инженерный ассистент |
| `assistant_question` | Задан вопрос ассистенту |
| `assistant_lead_form_opened` | В ассистенте открыта форма заявки |
| `assistant_lead_submit` | Заявка из ассистента отправлена |
| `assistant_lead_success` | Заявка из ассистента принята — дублируется в `ym-submit-leadform` |
| `assistant_lead_error` | Заявка из ассистента отклонена |

Пара `quote_request_error` и `assistant_lead_error` полезнее всего: рост этих целей означает, что
посетители пытаются оставить заявку, а сайт их теряет.

## Запуск рекламы в Яндекс Директе / РСЯ

Рекламные кампании требуют отдельного аккаунта Директа, оплаты и согласованного месячного бюджета. До запуска обязательно дождитесь накопления данных по цели `ym-submit-leadform`, затем создавайте кампании с оптимизацией на эту цель и исключением нецелевых регионов/аудиторий. Не запускайте рекламу по «клику на форму» вместо подтверждённой заявки.

Структура рекламного кабинета должна повторять структуру сайта: отдельные кампании или группы для
производственных операций, девяти видов фасадной продукции и шестнадцати типов объектов. Готовые
фразы, посадочные страницы и ограничения собраны в `SEMANTIC_CORE_RSYA.md`.

## Контроль после публикации

- Вебмастер → Индексирование → Статистика обхода: страницы доступны роботу.
- Вебмастер → Файлы Sitemap: статус обработки без ошибок.
- Метрика → Отчёты → Конверсии: видны события после тестовой заявки.
- Директ: для оптимизации используйте лишь данные Метрики и подтверждённые заявки.

Техническая оптимизация улучшает доступность и понятность сайта для поиска, но не может честно гарантировать первое место в выдаче: позиция зависит от конкуренции, региона, спроса и поведенческих факторов.
