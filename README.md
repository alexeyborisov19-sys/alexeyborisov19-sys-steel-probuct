# Сталь Продукт — v0.1.3

Стартовая версия корпоративного сайта «Сталь Продукт». Проект использует Next.js 15, App Router, TypeScript, Tailwind CSS и Framer Motion.

## Запуск локально

Требуется Node.js 22.13 или новее: архитектурный фундамент закрытой служебной
системы использует встроенный `node:sqlite`. Сама система по умолчанию выключена.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

## Production-сборка

```bash
npm run build
npm run start
```

## Структура

- `app/` — маршруты и глобальные стили App Router.
- `components/` — повторно используемые компоненты интерфейса.
- `data/` — контентные данные, которые позднее можно перенести в CMS.
- `public/` — брендовые файлы и изображения.

## Брендовый логотип

Утверждённый логотип размещён в `public/logo/steel-product.png` и используется единым компонентом `components/Brand.tsx` в Header и Footer.

## Каталог для менеджеров и печати

Актуальный переработанный каталог фасадных решений доступен в `public/documents/katalog-fasadnyh-resheniy-stal-produkt.pdf`. Это версия для печати на чисто белых листах в формате A4 с вылетами по 3 мм: графитовый текст, фирменные оранжевые акценты и очищенные технические рисунки без вставленных страниц исходного каталога.

Для короткой презентации есть `public/documents/katalog-fasadnyh-resheniy-kratkij-4-stranicy.pdf`: четыре последовательные страницы A4 для двусторонней печати на двух листах. Исходный скрипт - `work/generate_compact_print_catalog.py`.

Исходный файл находится в `work/generate_updated_catalog.py`. После правок запускайте его из корня проекта через Python с установленными `reportlab` и `Pillow`, затем копируйте результат в `public/documents/`. В каталоге используются действующие контакты и адрес производства: `г. Смоленск, Рославльское шоссе, 7-й км, стр. 3`.

## Деплой на Beget

На VPS установите Node.js 22.13+, затем:

```bash
git clone https://github.com/alexeyborisov19-sys/alexeyborisov19-sys-steel-probuct.git
cd alexeyborisov19-sys-steel-probuct
npm install
npm run build
npm run start
```

Для постоянной работы используйте `pm2`, а перед Node.js настройте Nginx как reverse proxy.

Для ручной публикации и будущих обновлений по вашему решению используйте [DEPLOYMENT.md](DEPLOYMENT.md). В проект включена PM2-конфигурация для стабильной работы сайта на VPS.

## Заявки с чертежами

Страница `/contacts#contact-form` принимает до 10 файлов суммарным объёмом до 10 МБ (один файл — до 7 МБ): PDF, DXF/DWG, STEP/IGES, CAD-файлы, изображения, офисные документы и архивы.

Для фактической отправки заявок на `info@steelprodukt.ru` скопируйте `.env.example` в `.env.local` и внесите SMTP-параметры почтового ящика. На Beget эти же переменные добавляются в окружение процесса `pm2`; пароль почты не должен попадать в Git.

Для Nginx на VPS задайте `client_max_body_size 11m;`: это соответствует
маршрутному лимиту формы и не позволяет reverse proxy принять существенно
больший запрос, чем приложение.

## Инженерный ИИ-помощник

Глобальный компонент `components/EngineeringAssistant.tsx` сопровождает клиента по продукции и технологическому процессу, уточняет исходные данные и регистрирует заявку с чертежами. Проверенная база знаний и ограничения ответов находятся в `data/assistant-knowledge.ts`.

Без внешнего API помощник работает в надёжном режиме локальной базы знаний. Для подключения генеративного контура Yandex AI Studio задайте на сервере `YANDEX_AI_ENABLED=true`, `YANDEX_AI_API_KEY`, `YANDEX_AI_FOLDER_ID` и при необходимости `YANDEX_AI_MODEL_URI`. Ключ никогда не передаётся в браузер. Контактные данные отделены от диалога и не отправляются модели.

Заявки сохраняются вне публичной директории. В production подготовьте каталог:

```bash
sudo install -d -m 700 -o nodejs -g nodejs /var/lib/steelprodukt/assistant-leads
```

и задайте `ASSISTANT_LEAD_STORAGE_PATH=/var/lib/steelprodukt/assistant-leads`.
Передача в Telegram в текущем коде отсутствует и не может быть включена
переменными environment.

## Персональные данные и правовая готовность

Публичные документы находятся в `app/(public)/legal/`: политика обработки персональных данных, отдельное согласие для формы, отдельное необязательное согласие на рекламу, политика cookies, реквизиты, пользовательское соглашение и реестр сервисов обработки данных.

Форма сохраняет непубличное доказательство согласия: идентификатор заявки, время, версии документов и хешированные контактные/сетевые данные. В production обязательно задайте:

```bash
CONSENT_AUDIT_STORAGE_PATH=/var/lib/steelprodukt/consent-audit
CONSENT_AUDIT_RETENTION_DAYS=1095
CONSENT_AUDIT_SALT=<отдельная случайная строка не менее 32 байт>
```

Каталог должен существовать на российском сервере, принадлежать пользователю
процесса Node.js и не раздаваться Nginx. Резервное копирование нельзя считать
действующим до настройки шифрования и успешной проверки восстановления. Папка
`.data/` исключена из Git и деплоя.

Архитектурный фундамент закрытой системы описан в
`docs/personal-data-stage-2-architecture.md`. Он выключен через
`PD_ADMIN_ENABLED=false`, не участвует в приёме заявок и не должен включаться
до завершения Этапа 3 и ручной проверки VPS.

Организационные действия, которые нельзя выполнить программным кодом, перечислены в [LEGAL_COMPLIANCE_RU.md](LEGAL_COMPLIANCE_RU.md). Реестр оснований использования фотографий, видео, логотипов, визуализаций и чертежей — в [LEGAL_MEDIA_RIGHTS_REGISTER.md](LEGAL_MEDIA_RIGHTS_REGISTER.md). Перед публикацией эти документы должен проверить ответственный за персональные данные и российский юрист.

## SEO, Яндекс, РСЯ и ИИ-поиск

В проекте настроены канонические URL, постраничные title/description, Open Graph, `sitemap.xml`, `robots.txt`, `Clean-param` для Яндекса, Schema.org для компании/услуг/товаров/FAQ и публичный `llms.txt` для дополнительных AI-инструментов.

Календарные материалы дополнительно размечены как `ExhibitionEvent` и `ItemList`, снабжены видимым FAQ, тематическими внутренними ссылками и расширенными поисковыми запросами. После публикации новой или обновлённой страницы можно уведомить Яндекс через IndexNow:

```bash
npm run indexnow:submit -- /articles/vystavki-fasady-arhitektura-2026
```

Команда не запускается автоматически при локальной разработке и не отправляет черновые страницы в поиск.

Полная инструкция по подключению Яндекс.Вебмастера, Яндекс.Метрики, целей РСЯ, региональности, контентному SEO и будущему самообучающемуся ИИ-контуру — в [SEO_AI_RUNBOOK.md](SEO_AI_RUNBOOK.md).

Готовые сильные формулировки, кластеры поискового спроса и заготовки объявлений для РСЯ — в [SEMANTIC_CORE_RSYA.md](SEMANTIC_CORE_RSYA.md). Они заложены в метаданные и тексты сайта, но не выводятся посетителю как неестественная «простыня ключей».

План статей, правила технической проверки и безопасный цикл «данные → гипотеза → обновление» находятся в [CONTENT_STRATEGY.md](CONTENT_STRATEGY.md).
